LLM Wiki란?

LLM Wiki는 원본 자료를 매번 처음부터 검색하고 조합하는 대신,

LLM이 자료를 읽고 정리한 결과를 지속적으로 축적하고 갱신하는 Markdown 기반 지식베이스입니다.

우리가 일반적으로 LLM과 문서를 활용하는 방식은 다음과 같습니다.

문서 업로드
→ 질문
→ 관련 문서 조각 검색
→ 답변 생성

ChatGPT 파일 업로드, NotebookLM, 일반적인 RAG 시스템도 대체로 이런 흐름을 사용합니다.

이 방식은 질문에 답하는 데 유용하지만, 한 가지 근본적인 한계가 있습니다.

LLM이 질문을 받을 때마다 관련 지식을 다시 찾아서 조합해야 한다는 점입니다.

예를 들어 다섯 개의 문서를 종합해야 답할 수 있는 질문이 있다면, LLM은 질문을 받을 때마다 다음 작업을 반복합니다.

관련 문서 찾기
→ 필요한 부분 읽기
→ 서로 연결하기
→ 충돌 확인하기
→ 답변 만들기

질문에 대한 답은 생성되지만, 이 과정에서 만들어진 구조와 연결 관계는 대화가 끝나면 사라질 수 있습니다. 즉, 지식이 계속 쌓이지 않습니다.

LLM Wiki는 이 문제에서 출발합니다.

원본 문서
→ LLM이 한 번 읽고 정리
→ 구조화된 Wiki에 반영
→ 다음 질문에서는 Wiki를 활용
→ 새로운 분석도 다시 Wiki에 축적

기존 RAG와 LLM Wiki의 차이

일반적인 RAG

RAG는 사용자의 질문과 관련된 문서 조각을 찾아 LLM에게 전달합니다.

질문
→ 원본 자료 검색
→ 관련 조각 검색
→ 답변 생성

장점은 분명합니다.

  • 많은 문서 중 관련 내용만 찾을 수 있습니다.
  • 모든 문서를 한꺼번에 입력하지 않아도 됩니다.
  • 원본 자료를 근거로 답변할 수 있습니다.

하지만 질문할 때마다 지식을 다시 구성해야 합니다.

LLM Wiki

LLM Wiki에서는 원본 자료와 사용자 사이에 지속적인 Wiki 계층이 존재합니다.

사용자
↕
LLM Wiki
↕
Raw Sources

새로운 자료가 추가되면 LLM은 단순히 검색 대상으로 등록하지 않습니다.

  • 핵심 내용을 추출합니다.
  • 기존 개념 문서를 갱신합니다.
  • 관련 인물이나 조직 페이지를 수정합니다.
  • 기존 주장과 충돌하는 내용을 표시합니다.
  • 여러 자료를 종합한 설명을 발전시킵니다.
  • 관련 페이지 사이에 링크를 연결합니다.

따라서 지식은 매 질문마다 새로 만들어지는 것이 아니라, 한 번 정리된 뒤 지속적으로 최신 상태를 유지합니다.

🔑 핵심 차이

RAG는 필요할 때 원본을 다시 찾아 답을 만듭니다.

LLM Wiki는 원본에서 얻은 지식을 미리 구조화하고 계속 축적합니다.

LLM Wiki는 ‘지속적으로 커지는 산출물’이다

LLM Wiki에서 중요한 것은 단순히 Markdown 파일이 있다는 사실이 아닙니다.

핵심은 Wiki가 다음 특성을 가진다는 점입니다.

1. 지속성

: LLM이 만든 요약과 분석이 채팅 안에서 사라지지 않고 파일로 남습니다.

2. 누적성

: 새로운 자료가 추가될 때 기존 Wiki가 함께 발전합니다.

3. 연결성

개념, 인물, 사건, 조직, 주장 사이의 관계가 링크로 연결됩니다.

4. 정합성

새로운 자료가 기존 설명과 충돌하면 관련 페이지를 함께 검토합니다.

5. 재사용성

한 번 만들어진 비교나 분석을 다음 질문에서 다시 활용할 수 있습니다.

카파시의 LLM WIKI에 대한 설명에서는 persistent, compounding artifact, 즉 지속적으로 복리처럼 성장하는 산출물로 설명합니다. 새로운 자료와 질문이 추가될수록 Wiki의 연결·모순 표시·종합 설명이 더 풍부해집니다.

사람과 LLM의 역할

LLM Wiki에서는 사람이 Wiki를 직접 계속 작성하는 것이 기본 모델이 아닙니다.

사람
= 좋은 자료를 선정한다.
= 탐구할 방향을 정한다.
= 좋은 질문을 한다.
= 결과가 어떤 의미인지 판단한다.

LLM
= 자료를 읽는다.
= 요약한다.
= 적절한 위치에 분류한다.
= 관련 페이지를 연결한다.
= 기존 내용을 갱신한다.
= 충돌과 누락을 관리한다.

원문에서는 사용자가 Wiki를 직접 작성하는 경우는 드물고, LLM이 요약·교차 참조·파일 정리·장부 관리 같은 반복 업무를 담당한다고 설명합니다. 사람은 자료 선정과 탐색, 올바른 질문, 해석에 집중합니다.

이를 개발 환경에 비유하면 다음과 같습니다.

Obsidian
= Wiki를 탐색하는 IDE

LLM Agent
= Wiki를 작성하고 유지하는 프로그래머

Markdown Wiki
= 관리되는 지식 코드베이스

사용자는 Obsidian 같은 도구로 페이지와 링크를 살펴보고, LLM은 대화 내용을 바탕으로 파일을 수정합니다.

LLM Wiki의 3계층 구조

LLM Wiki는 크게 세 계층으로 구성됩니다.

1. Raw Sources
2. Wiki
3. Schema

1. Raw Sources

Raw Sources는 사용자가 선별한 원본 자료 모음입니다.

예:

  • 기사
  • 논문
  • 책의 장별 메모
  • 이미지
  • 데이터 파일
  • 회의록
  • 인터뷰 기록
  • 팟캐스트 메모
  • 웹페이지
  • 개인 일지
핵심 원칙
  • 사람이 수집한다.
  • LLM은 읽는다.
  • LLM은 원본을 수정하지 않는다.

Raw Sources는 불변 자료입니다.

LLM이 원문을 요약하면서 내용을 잘못 해석했을 때, 다시 확인할 수 있는 기준이 되어야 하기 때문입니다.

예시 구조
raw/
├─ articles/
│  ├─ article-001.md
│  └─ article-002.md
├─ papers/
│  ├─ paper-001.pdf
│  └─ paper-002.pdf
├─ images/
├─ transcripts/
└─ data/

2. The Wiki

Wiki는 LLM이 생성하고 유지하는 Markdown 문서 모음입니다.

Wiki에는 다음과 같은 페이지가 들어갈 수 있습니다.

  • 자료별 요약
  • 인물 페이지
  • 기업·기관 페이지
  • 핵심 개념 페이지
  • 사건 페이지
  • 비교 페이지
  • 전체 개요
  • 여러 자료를 종합한 분석
  • 변화하는 가설이나 논지
  • 질문을 통해 새로 발견한 연결 관계
예시 구조
wiki/
├─ index.md
├─ log.md
├─ overview.md
├─ sources/
│  ├─ article-001-summary.md
│  └─ paper-001-summary.md
├─ entities/
│  ├─ person-a.md
│  └─ company-b.md
├─ concepts/
│  ├─ llm-agents.md
│  └─ retrieval-augmented-generation.md
├─ comparisons/
│  └─ rag-vs-llm-wiki.md
└─ synthesis/
   └─ evolving-thesis.md
LLM이 담당하는 작업
  • 새 페이지 생성
  • 기존 페이지 수정
  • 관련 페이지 링크 연결
  • 새로운 자료에 따른 요약 갱신
  • 오래된 주장 수정
  • 모순 표시
  • 중복 페이지 통합
  • 인덱스 갱신
  • 문서 간 일관성 유지

이 구조에서 사용자는 Wiki를 읽고 탐색하며, LLM이 Wiki를 작성하고 유지합니다.

3. The Schema

Schema는 LLM에게 Wiki를 어떻게 만들고 관리할지 알려주는 운영 규칙입니다.

Claude Code에서는 CLAUDE.md, Codex 계열에서는 AGENTS.md 같은 파일을 사용할 수 있습니다.

Schema에는 다음과 같은 내용이 들어갑니다.

  • 전체 디렉터리 구조
  • 파일 이름 규칙
  • 페이지별 목적
  • 링크 작성 방식
  • 출처 표기 규칙
  • Raw Sources 수정 금지 규칙
  • 새 자료 수집 절차
  • 질문 응답 절차
  • Wiki 점검 절차
  • index.md와 log.md 관리 방식
  • 중복·모순 처리 방법
  • YAML frontmatter 규칙
예시
# LLM Wiki Schema

## 계층

- `raw/`: 사람이 추가한 원본 자료. 수정 금지.
- `wiki/`: LLM이 생성하고 관리하는 지식 문서.
- `wiki/index.md`: 전체 페이지 색인.
- `wiki/log.md`: 작업 이력.

## 자료 수집 규칙

새로운 자료가 추가되면:

1. 원문을 읽는다.
2. 자료별 요약 페이지를 생성한다.
3. 관련 개념과 인물 페이지를 갱신한다.
4. 기존 주장과 충돌하는 내용을 표시한다.
5. index.md를 갱신한다.
6. log.md에 처리 기록을 추가한다.

## 작성 규칙

- 모든 주요 주장에 출처를 연결한다.
- 원본 자료를 수정하지 않는다.
- 중복 페이지를 만들기 전에 index.md를 확인한다.
- 새 자료가 기존 내용을 대체하면 이유를 기록한다.

Schema가 있기 때문에 LLM은 일반적인 챗봇이 아니라 규칙을 따르는 Wiki 관리자처럼 행동할 수 있습니다.

이 문서는 처음부터 완벽할 필요가 없습니다. 사용자가 Wiki를 운영하면서 자신에게 맞는 방식이 무엇인지 발견하면 LLM과 함께 계속 개선합니다.

1. Ingest: 새로운 자료를 지식베이스에 통합하기

Ingest는 단순한 파일 업로드가 아닙니다.

새 자료를 읽고 기존 Wiki 전체에 필요한 변화를 반영하는 과정입니다.
기본 흐름
새 원본 추가
→ LLM이 원본 읽기
→ 핵심 내용 논의
→ 자료 요약 페이지 생성
→ 관련 개념 페이지 갱신
→ 관련 인물·기관 페이지 갱신
→ 기존 주장과 충돌 확인
→ index 갱신
→ log 기록

하나의 자료가 여러 개념과 연결돼 있다면 한 번의 Ingest로 여러 Wiki 페이지가 함께 변경될 수 있습니다.

원문에서는 하나의 자료가 10~15개 페이지에 영향을 줄 수도 있다고 설명합니다. 또한 자료를 한 번에 하나씩 처리하며 사람이 요약과 업데이트를 확인할 수도 있고, 여러 자료를 일괄 처리할 수도 있다고 설명합니다. 중요한 것은 자신에게 맞는 처리 방식을 Schema에 기록하는 것입니다.

예시

새 논문:

raw/papers/llm-memory-2026.pdf

Ingest 후 변경:

wiki/sources/llm-memory-2026.md      # 논문 요약 생성
wiki/concepts/llm-memory.md          # 개념 내용 갱신
wiki/concepts/rag.md                 # 비교 내용 추가
wiki/comparisons/rag-vs-memory.md    # 비교표 갱신
wiki/synthesis/knowledge-systems.md  # 종합 분석 수정
wiki/index.md                        # 신규 페이지 등록
wiki/log.md                          # 처리 내역 기록

2. Query: Wiki를 바탕으로 질문하고 결과를 다시 축적하기

Query는 Wiki에 질문하는 과정입니다.

질문
→ index에서 관련 페이지 찾기
→ 필요한 Wiki 페이지 읽기
→ 필요하면 원본 확인
→ 답변 종합
→ 출처와 함께 제공

답변은 다양한 형식으로 만들 수 있습니다.

  • Markdown 문서
  • 비교표
  • 보고서
  • 프레젠테이션
  • 차트
  • 캔버스
  • 새로운 개념 페이지

여기서 중요한 점은 좋은 답변을 채팅에만 남기지 않는 것입니다.

예를 들어 사용자가 다음 질문을 했다고 가정해봅시다.

✍️ 요청문
RAG와 LLM Wiki의 차이를 비교해줘.

LLM이 유용한 비교표와 분석을 만들었다면 이를 새 문서로 저장할 수 있습니다.

wiki/comparisons/rag-vs-llm-wiki.md

이제 다음 질문에서는 이 분석을 다시 처음부터 만들 필요가 없습니다.

원문에서는 비교, 분석, 새로 발견한 연결처럼 가치 있는 답변을 Wiki에 다시 저장하면 탐색 결과까지 지식베이스에 누적된다고 설명합니다.

3. Lint: Wiki의 건강 상태 점검하기

Wiki가 커질수록 페이지가 늘어나고 서로 충돌할 수 있습니다.

Lint는 LLM에게 Wiki 전체를 점검하도록 요청하는 과정입니다.

점검 항목
  • 서로 모순되는 페이지가 있는가?
  • 새로운 자료가 오래된 주장을 대체했는가?
  • 아무 페이지에서도 연결되지 않은 고립 페이지가 있는가?
  • 자주 언급되지만 독립 페이지가 없는 개념이 있는가?
  • 필요한 교차 링크가 빠져 있는가?
  • 같은 내용을 중복해서 설명하는 페이지가 있는가?
  • 출처가 부족한 주장이 있는가?
  • 추가 조사가 필요한 데이터 공백이 있는가?
예시 요청
✍️ 요청문
Wiki 전체를 점검해줘.

- 서로 충돌하는 주장
- 오래된 정보
- 링크가 없는 고립 페이지
- 별도 페이지가 필요한 중요 개념
- 누락된 교차 참조
- 추가 자료가 필요한 영역

을 찾아서 수정 제안을 작성해줘.

Lint는 단순한 오탈자 검사가 아닙니다.

지식베이스의 연결성·최신성·정합성을 유지하는 작업입니다.

원문에서는 LLM이 새로운 조사 질문과 추가할 자료까지 제안할 수 있으며, 이런 점검을 통해 Wiki가 성장해도 건강하게 유지된다고 설명합니다.

index.md와 log.md

Wiki가 커지면 두 가지 특별한 문서가 중요해집니다.

index.md
= 무엇이 어디에 있는가?

log.md
= 언제 무엇을 했는가?

index.md: 콘텐츠 중심 색인

index.md는 Wiki 전체의 지도입니다.

각 페이지에 대해 다음 내용을 기록할 수 있습니다.

  • 문서 링크
  • 한 줄 설명
  • 분류
  • 작성일 또는 갱신일
  • 관련 원본 개수
  • 주요 태그
예시
# Wiki Index

## Overview

- [[overview]] — 전체 지식베이스 개요
- [[synthesis/evolving-thesis]] — 현재까지의 종합 논지

## Concepts

- [[concepts/rag]] — 검색 증강 생성의 구조와 한계
- [[concepts/llm-wiki]] — LLM 기반 누적형 지식베이스
- [[concepts/knowledge-compounding]] — 지식 누적과 재사용

## Comparisons

- [[comparisons/rag-vs-llm-wiki]] — 두 접근 방식 비교

## Sources

- [[sources/article-001]] — LLM Wiki 아이디어 원문 요약

LLM은 질문을 받으면 먼저 index.md를 읽고 관련 페이지를 찾을 수 있습니다.

약 100개의 자료와 수백 개 수준의 페이지까지는 이런 색인만으로도 유용하게 탐색할 수 있으며, 반드시 처음부터 임베딩 기반 RAG 시스템을 만들 필요는 없습니다.

log.md: 시간 중심 작업 기록

log.md는 Wiki가 어떻게 변화했는지 보여주는 시간순 기록입니다.

원문은 이 문서를 추가 전용(append-only) 기록으로 규정합니다. 새 항목은 항상 아래에 덧붙이고, 이미 기록한 항목은 수정하거나 삭제하지 않습니다.

  • 과거에 어떤 판단을 왜 내렸는지 나중에 추적할 수 있습니다.
  • Wiki 페이지가 바뀐 이유를 되짚을 근거가 남습니다.
  • 기록을 고치기 시작하면 Wiki의 실제 변경 이력과 로그가 어긋납니다.

이전 기록에 오류가 있다면 그 항목을 수정하는 대신, 새 항목에 정정 사실을 기록합니다.

## [2026-07-25] correction | 07-22 query 기록 정정

- 이전 기록에서 비교 대상 자료를 잘못 표기했다.
- 실제 비교 대상: sources/경쟁브랜드-루테인-분석
- 원 기록은 그대로 두고 이 항목으로 정정한다.
기록 대상
  • 새로운 자료 Ingest
  • 중요한 Query
  • Wiki에 저장된 분석
  • Lint 실행
  • 구조 변경
  • Schema 변경
예시
# Wiki Log

일관된 제목 형식을 사용하면 간단한 명령어로 최근 기록을 확인할 수도 있습니다.

grep"^## \[" log.md | tail-5

index.md와 log.md의 차이는 명확합니다.

문서기준답하는 질문
index.md콘텐츠어떤 지식이 어디에 있는가?
log.md시간Wiki에서 언제 무엇이 일어났는가?

log.md 는 Ingest·Query·Lint의 시간순 기록이며, Wiki가 최근 어떻게 변화했는지 LLM이 이해하는 데 도움을 줍니다.

LLM Wiki는 어디에 활용할 수 있는가?

1. 개인 지식 관리

다음 자료를 한곳에 축적할 수 있습니다.

  • 개인 목표
  • 건강 기록
  • 심리·감정 일지
  • 자기계발 자료
  • 읽은 기사
  • 팟캐스트 메모
  • 회고

예:

Raw Sources
= 일기, 건강 기록, 읽은 기사, 팟캐스트 메모

Wiki
= 목표 페이지, 습관 페이지, 건강 경향, 반복되는 문제,
  장기 변화, 중요한 사건 사이의 관계

시간이 지나면 단순한 메모 모음이 아니라 자신에 대한 구조화된 그림을 만들 수 있습니다.

2. 장기 리서치

몇 주 또는 몇 달 동안 하나의 주제를 연구할 때 사용할 수 있습니다.

논문
기사
보고서
인터뷰
통계 데이터

를 계속 추가하면서 다음을 발전시킬 수 있습니다.

  • 핵심 개념
  • 주요 연구자
  • 서로 다른 주장
  • 논쟁 지점
  • 연구 결과 비교
  • 계속 변화하는 종합 논지

일반적인 폴더는 자료를 저장하지만, LLM Wiki는 자료 사이의 관계와 축적된 해석을 관리합니다.

3. 책 읽기

책을 장별로 읽으며 Wiki를 만들 수도 있습니다.

Raw Sources
= 각 장의 메모 또는 원문

Wiki
= 등장인물, 장소, 사건, 주제, 복선, 인물 관계,
  장별 요약, 전체 줄거리

판타지나 역사서처럼 등장인물과 사건이 많은 책에 특히 적합합니다.

책을 다 읽을 때쯤에는 개인용 동반 Wiki가 완성됩니다. 원문은 인물·장소·사건·언어가 연결된 팬 Wiki와 유사한 개인 지식베이스를 LLM이 유지할 수 있다고 설명합니다.

4. 비즈니스와 팀

뉴트리원에서 발생하는 다음 자료를 Raw Sources로 사용할 수 있습니다.

  • 사내 메신저·메일 논의
  • 주간회의록과 회의 녹취
  • 제품 기획서와 상세페이지 원고
  • 고객문의(VOC)와 오픈마켓 리뷰
  • 영업·MD 미팅 기록
  • 표시·광고 심의 및 사내 규정 문서
  • 원료·기능성 리서치 자료

LLM은 이를 바탕으로 다음 Wiki를 관리할 수 있습니다.

  • 원료와 기능성 개념
  • 제품·브랜드 페이지
  • 고객이 반복해서 묻는 질문
  • 채널별 운영 규칙
  • 경쟁 브랜드 비교
  • 사내 용어 사전
  • 프로젝트별 지식
  • 회의에서 나온 주요 결정과 논점

팀이 직접 Wiki를 계속 정리하지 않아도 LLM이 유지보수를 담당하므로 문서가 오래된 상태로 방치되는 문제를 줄일 수 있습니다. 표시·광고 문구나 고객 응대 기준처럼 민감하거나 중요한 변경에는 담당자가 검토하는 절차를 추가합니다.

5. 그 밖의 활용

  • 경쟁 브랜드 분석
  • 신규 원료·소재 조사
  • 채널·유통사 정보 정리
  • 교육·강의 노트
  • 신제품 컨셉 조사
  • 표시·광고 등 법규 자료 정리
  • 캔페인 회고와 사례 정리
  • 콘텐츠·키워드 리서치

공통 조건은 하나입니다.

시간이 지나면서 자료가 계속 쌓이고, 그 자료를 흩어진 상태가 아니라 구조화된 지식으로 유지하고 싶을 때 적합합니다.

왜 LLM Wiki가 작동하는가?

사람들이 Wiki를 포기하는 이유는 지식을 읽거나 생각하는 일이 어려워서만은 아닙니다.

더 큰 문제는 유지보수입니다.

  • 새 페이지를 적절한 위치에 배치합니다.
  • 관련 문서에 링크를 추가합니다.
  • 오래된 요약을 갱신합니다.
  • 새로운 자료와 충돌하는 주장을 수정합니다.
  • 중복 페이지를 정리합니다.
  • 색인과 메타데이터를 관리합니다.
  • 여러 페이지의 표현을 일관되게 유지합니다.

문서가 많아질수록 이런 관리 비용은 커집니다.

LLM은 이런 반복 관리 작업에 적합합니다.

사람
= 지식의 의미와 방향을 판단

LLM
= 반복되는 정리와 유지보수 수행

원문에서는 인간이 Wiki를 포기하는 이유를 유지 비용이 가치보다 빠르게 증가하기 때문이라고 설명합니다. 반면 LLM은 여러 페이지를 한 번에 수정하고 교차 참조를 갱신하는 작업을 반복적으로 수행할 수 있어 유지 비용을 크게 낮출 수 있습니다.

Memex와의 관계

LLM Wiki 아이디어는 버니바 부시가 1945년에 제안한 Memex와 정신적으로 연결됩니다.

Memex는 개인이 수집한 자료를 저장하고, 자료 사이의 연관 경로를 따라 탐색하는 지식 장치를 구상한 개념입니다.

핵심은 단순히 자료를 많이 저장하는 것이 아니었습니다.

문서 A
↔ 관련 개념
↔ 문서 B
↔ 사건 C
↔ 새로운 해석

자료 사이의 연결 자체가 중요한 지식이라는 생각입니다.

하지만 당시에는 누가 그 연결과 정리를 지속적으로 관리할지가 해결되지 않았습니다.

LLM Wiki에서는 LLM이 그 유지보수 역할을 맡습니다. 카파시는 Memex의 개인적·능동적·연결 중심 지식 저장소라는 비전과 LLM Wiki가 유사하며, 당시 해결하기 어려웠던 관리 문제를 LLM이 담당한다고 설명합니다.

원문이 제시하는 Obsidian 설정 순서는 다음과 같습니다.

1. Settings → Files and links → Attachment folder path
   = 고정 경로 지정 (예: raw/assets/)

2. Settings → Hotkeys → "Download" 검색
   = "Download attachments for current file"에 단축키 지정
     (예: Ctrl+Shift+D)

3. 기사를 클리핑한 뒤 단축키 실행
   = 해당 문서의 이미지가 모두 로컬 디스크에 저장됨

이렇게 하면 LLM이 깨질 수 있는 URL에 의존하지 않고 이미지를 직접 참조할 수 있습니다. 필수는 아니며 자료가 텍스트뿐이라면 건너뛰어도 됩니다.

다만 현재 LLM은 인라인 이미지가 포함된 Markdown을 한 번에 읽지 못합니다. 원문이 제시하는 우회 방법은 다음과 같습니다.

1단계: LLM이 문서의 텍스트를 먼저 읽는다.
2단계: 참조된 이미지를 별도로 확인해 추가 맥락을 얻는다.

다소 번거로우지만 실용적으로는 충분히 작동한다고 설명합니다.

실습 : 뉴트리원 업무 지식베이스용 LLM Wiki 시작하기

LLM Wiki는 우리가 만들고 받은 자료를 단순히 저장하는 폴더가 아닙니다.

제품 기획서, 원료 자료, 고객문의 내역, 오픈마켓 리뷰, 회의록과 같은 업무 자료를 LLM이 읽고 정리하여, 서로 연결된 Markdown Wiki로 지속적으로 발전시키는 업무 지식 관리 시스템입니다.

일반적인 문서 검색 방식에서는 질문할 때마다 LLM이 관련 자료를 다시 찾고 조합해야 합니다. 반면 LLM Wiki에서는 이미 정리된 원료·제품 개념, 담당 조직, 자료, 주제, 질문과 통찰이 Wiki에 누적됩니다.

새로운 자료가 들어오면 LLM은 단순히 요약문 하나를 추가하는 데 그치지 않습니다.

  • 기존 개념 페이지를 갱신합니다.
  • 관련된 제품과 담당 조직 페이지를 연결합니다.
  • 이전 판단과 충돌하는 내용을 표시합니다.
  • 여러 자료에서 반복되는 패턴을 종합합니다.
  • 새롭게 생긴 질문과 확인할 과제를 기록합니다.

업무용 LLM Wiki의 목적은 모든 자료를 완벽하게 보관하는 것이 아니라, 시간이 지날수록 팀이 반복해서 쓰는 판단 근거가 구조화된 지식 체계로 남도록 돕는 것입니다.

최소 WIKI 구성

LLM Wiki는 고정된 구현 규격이 아닙니다.

어떤 자료를 관리할지, 어떤 LLM 도구를 사용할지, 얼마나 세밀하게 정리할지에 따라 구조를 다르게 만들 수 있습니다.

처음부터 복잡한 분류 체계나 검색 시스템을 만들 필요는 없습니다. 업무 지식 관리에서는 다음 정도의 최소 구조로 시작할 수 있습니다.

nutrione-llm-wiki/
├─ CLAUDE.md
├─ raw/
│  └─ README.md
└─ wiki/
   ├─ index.md
   └─ log.md

각 계층의 역할은 다음과 같습니다.

raw/
= 내가 수집한 업무 원본 자료

wiki/
= LLM이 원본 자료를 바탕으로 작성하고 관리하는 지식 페이지

CLAUDE.md
= LLM이 자료를 처리하고 Wiki를 관리하는 방법을 정의한 Schema

# Raw Sources

이 폴더에는 뉴트리원 업무 지식베이스를 위해 수집한 원본 자료를 저장한다.

예:

- 제품 기획서와 상세페이지 원고
- 원료·기능성 관련 자료와 논문 요약
- 고객문의(VOC) 내역과 오픈마켓 리뷰
- 주간회의록과 월간보고서
- 경쟁 브랜드 상세페이지 분석
- 표시·광고 심의 및 사내 규정 문서
- 채널·MD 미팅 기록
- 캔페인 실행 기록과 회고

운영 원칙:

- LLM은 이 폴더의 파일을 읽을 수 있다.
- LLM은 원본 파일을 수정하거나 덮어쓰지 않는다.
- 원본의 제목, 작성 부서, 출처, 수집일을 가능한 한 기록한다.
- 사내에서 작성한 기록과 외부 자료를 구분한다.
- 불확실한 출처는 불확실하다고 표시한다.

Raw Sources는 업무 지식베이스의 근거 자료입니다.

LLM이 작성한 Wiki 페이지에 오류가 있거나 해석이 의심스러울 경우, 언제든지 Raw Sources로 돌아가 원래 내용을 확인할 수 있어야 합니다.

# Personal LLM Wiki Schema

## 목적

이 저장소는 내가 수집한 책, 기사, 강의, 메모, 일기와
프로젝트 기록을 LLM이 구조화된 Markdown Wiki로 정리하고
지속적으로 갱신하기 위한 개인 지식 관리 시스템이다.

이 Wiki의 목적은 자료를 단순히 요약하는 것이 아니다.

- 서로 다른 자료 사이의 연결을 찾는다.
- 반복되는 개념과 관심사를 발견한다.
- 나의 생각이 어떻게 변하는지 기록한다.
- 기존 주장과 새로운 정보의 충돌을 표시한다.
- 재사용할 가치가 있는 분석과 통찰을 축적한다.

## 계층

### Raw Sources

- 위치: `raw/`
- 사용자가 직접 자료를 추가한다.
- 책 메모, 기사, 강의 노트, 일기, 아이디어 등을 포함할 수 있다.
- LLM은 읽기만 한다.
- LLM은 원본을 수정하거나 삭제하지 않는다.
- 원본은 Wiki 내용의 근거 자료로 사용한다.

### Wiki

- 위치: `wiki/`
- LLM이 생성하고 유지한다.
- 자료별 요약뿐 아니라 개념, 인물, 질문, 비교, 종합 페이지를 작성한다.
- 페이지 간 내부 링크를 적극적으로 사용한다.
- 주요 주장에는 관련 원본을 표시한다.
- 새로운 자료가 들어오면 기존 페이지도 함께 갱신한다.

### Schema

- 위치: `CLAUDE.md` or `AGENTS.md`
- Wiki의 구조와 운영 원칙을 정의한다.
- Ingest, Query, Lint 작업 방식을 정의한다.
- 사용하면서 발견한 개선 사항을 지속적으로 반영한다.

## 기본 페이지 유형

필요한 경우 다음 페이지 유형을 사용한다.

- `sources/`: 책, 기사, 강의, 영상 등 개별 자료
- `concepts/`: 반복해서 등장하는 핵심 개념
- `people/`: 저자, 연구자, 사상가, 주요 인물
- `questions/`: 장기간 탐구할 질문
- `comparisons/`: 서로 다른 주장과 관점의 비교
- `reflections/`: 사용자의 생각, 변화, 회고
- `synthesis/`: 여러 자료를 종합한 분석

페이지 유형은 필요할 때만 추가한다.

## 필수 문서

- `wiki/index.md`
  - 전체 페이지 목록
  - 각 페이지의 한 줄 설명
  - 주제별 분류

- `wiki/log.md`
  - Ingest, Query, Lint 작업 기록
  - Wiki의 주요 변화
  - 새롭게 생긴 질문

## Ingest

새 자료를 처리할 때:

1. 원본 전체를 읽는다.
2. 자료의 목적과 핵심 주장을 파악한다.
3. 중요한 근거, 사례, 개념을 추출한다.
4. 자료 요약 페이지를 생성한다.
5. 관련 개념, 인물, 질문 페이지를 생성하거나 갱신한다.
6. 기존 Wiki 내용과 일치하거나 충돌하는 부분을 확인한다.
7. 사용자의 기존 생각과 연결되는 부분이 있으면 표시한다.
8. 페이지 사이의 내부 링크를 추가한다.
9. `index.md`를 갱신한다.
10. `log.md`에 작업 내용을 기록한다.

자료에 없는 내용을 사실처럼 추가하지 않는다.

LLM의 추론이 포함될 경우 다음과 같이 구분한다.

- 원본에 직접 제시된 내용
- 여러 자료를 종합한 해석
- LLM이 제안한 가설
- 사용자가 추가로 검토해야 할 질문

## Query

질문에 답할 때:

1. `index.md`를 먼저 읽는다.
2. 질문과 관련된 Wiki 페이지를 찾는다.
3. 관련 개념, 자료, 인물, 질문 페이지를 함께 확인한다.
4. Wiki만으로 근거가 부족한 경우 Raw Sources를 확인한다.
5. 사실, 해석, 추론을 구분하여 답한다.
6. 관련 원본과 Wiki 페이지를 표시한다.
7. 재사용 가치가 있는 결과인지 판단한다.
8. 가치가 있다면 새 Wiki 페이지로 저장하거나 기존 페이지를 갱신한다.

모든 질문을 Wiki에 저장하지 않는다.

다음과 같은 결과를 우선적으로 저장한다.

- 여러 자료를 종합한 분석
- 반복해서 참고할 설명
- 중요한 비교
- 기존 생각을 수정하는 발견
- 장기적으로 탐구할 질문
- 새로운 연결과 패턴

## Lint

정기적으로 다음을 확인한다.

- 서로 모순되는 주장
- 새로운 자료에 의해 오래된 정보가 된 내용
- 원본 출처가 없는 주장
- 연결되지 않은 고립 페이지
- 본문에서 반복되지만 별도 페이지가 없는 중요 개념
- 같은 내용을 다루는 중복 페이지
- 잘못 연결된 인물이나 개념
- 사용자의 생각과 외부 자료가 구분되지 않은 부분
- 추가 조사가 필요한 질문
- 최근 갱신되지 않은 핵심 페이지

문제를 발견하면 바로 대규모로 수정하지 않는다.

먼저 다음 내용을 사용자에게 보여준다.

1. 발견한 문제
2. 수정이 필요한 이유
3. 영향을 받는 페이지
4. 제안하는 수정 계획

처음 사용하는 사람을 위한 운영 순서

1단계: 관리할 지식 영역 정하기

처음부터 삶의 모든 자료를 하나의 Wiki에 넣을 필요는 없습니다.

먼저 장기간 관심을 가지고 탐구할 한 가지 영역을 선택합니다.

처음 시작하기 좋은 기준은 다음과 같습니다.

  • 앞으로도 자료가 계속 추가될 주제
  • 여러 책이나 글을 함께 비교할 주제
  • 반복해서 질문하게 되는 주제
  • 나의 생각이 시간에 따라 달라질 수 있는 주제

예를 들어 다음과 같이 목적을 정할 수 있습니다.

생산성, 집중력, 습관 형성에 관한 책과 글을 정리하고,
서로 다른 저자들의 주장을 비교하며,
나에게 실제로 효과가 있었던 방법을 기록한다.

2단계: Raw Sources 추가하기

처음에는 3~5개 정도의 자료로 시작합니다.

raw/
├─ books/
│  ├─ 아주-작은-습관의-힘.md
│  └─ 딥워크.md
├─ articles/
│  └─ 스마트폰과-주의력.md
└─ personal/
   ├─ 나의-집중력-문제.md
   └─ 지난달-습관-회고.md

자료에는 가능한 한 기본 정보를 함께 기록합니다.

# 아주 작은 습관의 힘

여기에 책을 읽으며 작성한 메모를 기록한다.

외부 자료와 개인 기록을 구분하는 것이 좋습니다.

외부 자료
= 책, 기사, 논문, 강의 등

개인 자료
= 일기, 회고, 아이디어, 실험 결과, 경험 기록

이 둘을 구분하면 나중에 다음 질문에 더 정확하게 답할 수 있습니다.

  • 어떤 내용이 저자의 주장인가
  • 어떤 내용이 나의 생각인가
  • 어떤 내용이 실제 경험을 통해 확인되었는가
  • 어떤 내용이 아직 검증되지 않은 가설인가

3단계: 첫 Ingest 실행하기

첫 번째 자료는 한 번에 하나씩 처리하는 것이 좋습니다.

✍️ 예시 프롬프트:
CLAUDE.md를 먼저 읽어줘.

raw/books/아주-작은-습관의-힘.md를
개인 지식 관리 Wiki에 Ingest해줘.

다음 원칙을 지켜줘.

1. 원본 파일은 수정하지 않는다.
2. 자료의 핵심 주장과 근거를 구분한다.
3. wiki/sources/에 자료 요약 페이지를 작성한다.
4. 필요한 개념 페이지를 생성한다.
5. 기존 Wiki 페이지와 연결되는 내용이 있으면 갱신한다.
6. 원본에 없는 해석은 사실처럼 작성하지 않는다.
7. LLM의 해석이나 추론은 별도로 표시한다.
8. index.md와 log.md를 갱신한다.
9. 추가로 탐구할 질문을 제안한다.

첫 Ingest 이후에는 다음과 같은 페이지가 만들어질 수 있습니다.

wiki/
├─ index.md
├─ log.md
├─ sources/
│  └─ 아주-작은-습관의-힘.md
├─ concepts/
│  ├─ 습관-형성.md
│  ├─ 정체성-기반-습관.md
│  └─ 환경-설계.md
└─ questions/
   └─ 작은-행동은-언제-습관이-되는가.md

한 자료가 여러 Wiki 페이지를 갱신하는 것은 정상입니다.

자료 요약 페이지 하나만 만드는 것이 아니라, 기존 지식 구조 전체에 새로운 내용을 통합하는 것이 LLM Wiki의 핵심입니다.

4단계: 두 번째 자료 연결하기

두 번째 자료를 추가할 때는 첫 자료와 어떤 관계가 있는지 확인하도록 요청합니다.

✍️ 예시 프롬프트:
raw/books/딥워크.md를 Ingest해줘.

기존 Wiki의 다음 내용을 함께 확인해줘.

- 습관 형성과 연결되는 부분
- 집중력을 방해하는 환경 요인
- 반복 훈련과 정체성의 관계
- 기존 주장과 충돌하는 부분

새 자료 요약만 작성하지 말고,
관련 개념 페이지와 질문 페이지도 갱신해줘.

수정한 페이지 목록과 수정 이유를 마지막에 보여줘.

이 과정을 통해 개별 자료들이 독립적인 요약문으로 남지 않고 서로 연결되기 시작합니다.

예:

[[습관-형성]]
→ 반복 행동이 자동화되는 과정

[[딥워크]]
→ 집중 능력을 훈련하는 방법

[[환경-설계]]
→ 습관과 집중을 방해하거나 촉진하는 조건

[[디지털-산만함]]
→ 스마트폰과 알림이 집중에 미치는 영향

5단계: Wiki 탐색하기

자료가 몇 개 쌓이면 Wiki를 대상으로 질문할 수 있습니다.

핵심 개념 확인
✍️ 요청문
현재 개인 Wiki에서 가장 중요한 개념 5개를 설명해줘.

각 개념에 대해 다음을 포함해줘.

- 개념의 정의
- 관련 자료
- 다른 개념과의 연결
- 아직 해결되지 않은 질문
자료 간 비교
✍️ 요청문
제임스 클리어와 칼 뉴포트의 주장을 비교해줘.

다음 기준으로 정리해줘.

- 행동 변화의 출발점
- 환경의 역할
- 반복과 훈련의 역할
- 실천 방법
- 서로 보완되는 부분
- 충돌하거나 강조점이 다른 부분
개인 기록과 외부 자료 연결
✍️ 요청문
내가 작성한 집중력 회고와
현재 Wiki의 집중 관련 개념을 비교해줘.

다음을 구분해줘.

- 내 경험과 자료가 일치하는 부분
- 내 경험과 자료가 다른 부분
- 아직 판단하기 어려운 부분
- 다음 달에 실험해볼 행동
생각의 변화 확인
✍️ 요청문
지금까지의 log.md와 reflection 페이지를 바탕으로
내가 습관 형성에 대해 생각하는 방식이
어떻게 변했는지 설명해줘.

변화가 확인되는 근거 페이지도 함께 표시해줘.

6단계: 좋은 결과를 Wiki에 저장하기

질문에 대한 모든 답변을 Wiki에 저장할 필요는 없습니다.

여러 자료를 종합한 비교나, 앞으로 반복해서 참고할 분석은 Wiki에 저장할 가치가 있습니다.

✍️ 예시 프롬프트:
방금 만든 습관 형성과 딥워크의 비교 분석은
앞으로 다시 참고할 가치가 있다.

wiki/comparisons/습관-형성과-딥워크.md로 저장해줘.

다음을 함께 처리해줘.

1. 관련 개념 페이지에 링크를 추가한다.
2. 관련 자료 페이지에 역링크를 추가한다.
3. index.md를 갱신한다.
4. log.md에 Query 결과 저장을 기록한다.
5. 근거 자료와 LLM의 해석을 구분한다.

저장하기 좋은 결과는 다음과 같습니다.

  • 여러 책의 주장 비교
  • 여러 자료를 종합한 개념 설명
  • 개인 경험과 외부 연구의 비교
  • 반복해서 사용할 체크리스트
  • 장기간 탐구할 질문
  • 기존 생각이 바뀐 이유
  • 프로젝트의 주요 의사결정
  • 서로 떨어져 있던 주제 사이의 새로운 연결

저장하지 않아도 되는 결과는 다음과 같습니다.

  • 파일 위치 확인
  • 단순한 날짜 계산
  • 일회성 형식 변환
  • 이미 Wiki에 있는 내용의 단순 반복
  • 다시 사용할 가능성이 낮은 짧은 질문
  • 근거가 부족한 임시 아이디어

7단계: 개인적인 통찰 기록하기

개인 지식 관리에서는 외부 자료뿐 아니라 나의 생각과 경험도 중요한 자료입니다.

다만 개인적인 경험을 일반적인 사실처럼 기록하지 않도록 구분해야 합니다.

raw/personal/과 같은 경로에 다음과같이 저장해서 사용할 수 있습니다.

8단계: 주기적으로 Lint 실행하기

Wiki가 커지면 페이지 수만 늘어나는 것이 아니라 오류와 불일치도 함께 늘어날 수 있습니다.

✍️ 예시 프롬프트:
전체 개인 Wiki를 Lint해줘.

다음 항목을 확인해줘.

- 서로 모순되는 주장
- 오래된 정보
- 고립된 페이지
- 누락된 내부 링크
- 중복 페이지
- 출처가 부족한 주장
- 개인 경험과 일반 사실이 섞인 부분
- 같은 인물을 다른 이름으로 만든 페이지
- 본문에서 자주 등장하지만 독립 페이지가 없는 개념
- 추가 조사가 필요한 질문
- 최근 자료가 기존 종합 페이지에 반영되지 않은 부분

바로 수정하지 말고 먼저 변경 계획을 보여줘.

각 문제에 대해 다음을 포함해줘.

1. 문제가 있는 페이지
2. 문제의 내용
3. 수정이 필요한 이유
4. 제안하는 수정 방법
5. 영향을 받는 다른 페이지

변경 계획을 확인한 뒤 다음과 같이 요청할 수 있습니다.

✍️ 요청문
제안한 변경 계획 중 다음 항목만 적용해줘.

- 중복된 집중력 페이지 통합
- 오래된 스마트폰 사용 통계 표시
- 습관 형성 페이지에 딥워크 링크 추가

원본 자료는 수정하지 말고,
변경한 내용을 log.md에 기록해줘.

자동화 수준 선택하기

개인 지식 관리용 LLM Wiki에도 하나의 정답은 없습니다.

사용자가 자료를 얼마나 깊게 읽고 싶은지, LLM의 판단을 얼마나 검토하고 싶은지에 따라 운영 방식을 선택할 수 있습니다.

사람 참여가 많은 방식

자료 1개 추가
→ LLM과 핵심 내용 논의
→ Wiki 변경 계획 확인
→ 페이지별 수정 내용 검토
→ Wiki 반영
→ 후속 질문 작성

이 방식은 독서, 연구, 자기 이해처럼 자료를 깊이 탐구할 때 적합합니다.

장점:

  • 자료의 의미를 깊이 이해할 수 있습니다.
  • 어떤 내용을 강조할지 직접 결정할 수 있습니다.
  • 개인적인 관심사와 연결하기 쉽습니다.
  • 잘못된 종합을 빠르게 발견할 수 있습니다.
  • Wiki 구조를 사용하면서 세밀하게 개선할 수 있습니다.

단점:

  • 자료 처리 속도가 느립니다.
  • 사용자가 지속적으로 참여해야 합니다.
  • 많은 자료를 한꺼번에 처리하기 어렵습니다.

자동화가 많은 방식

자료 여러 개 추가
→ 일괄 Ingest
→ 자료 페이지 자동 생성
→ 관련 개념 페이지 자동 갱신
→ 결과 사후 검토

이 방식은 뉴스 기사, 회의 기록, 반복되는 강의 자료처럼 자료의 양이 많을 때 사용할 수 있습니다.

장점:

  • 많은 자료를 빠르게 처리할 수 있습니다.
  • 반복적인 분류와 링크 작업이 줄어듭니다.
  • 여러 자료에서 공통 주제를 빠르게 찾을 수 있습니다.

단점:

  • 잘못된 분류가 여러 페이지로 확산될 수 있습니다.
  • 중요하지 않은 내용이 과도하게 구조화될 수 있습니다.
  • 개인의 관심사와 다른 방향으로 Wiki가 성장할 수 있습니다.
  • 비슷하지만 다른 개념을 하나로 합칠 수 있습니다.
  • 자료의 미묘한 맥락을 놓칠 수 있습니다.

처음에는 자료를 한 번에 하나씩 Ingest하면서 Schema를 다듬는 방식이 좋습니다.

몇 번의 Ingest를 거치면서 다음 항목을 구체화할 수 있습니다.

  • 어떤 페이지 유형이 필요한가
  • 어떤 내용은 저장하지 않을 것인가
  • 출처를 어떻게 표시할 것인가
  • 개인 생각과 외부 자료를 어떻게 구분할 것인가
  • LLM이 어느 범위까지 자동 수정할 수 있는가
  • 어떤 변경은 반드시 사람의 승인을 받아야 하는가

개인 지식 관리용 LLM Wiki 사용 시 주의할 점

1. Wiki는 원본이 아니다

LLM이 작성한 Wiki는 원본 자료를 구조화하고 종합한 결과입니다.

따라서 해석 오류, 누락, 과도한 일반화가 포함될 수 있습니다.

Raw Sources
= 책, 기사, 강의, 메모와 같은 원본 근거

Wiki
= LLM이 원본을 정리하고 연결한 지식 구조

중요한 주장이나 의사결정에 사용되는 내용은 Raw Sources에서 다시 확인할 수 있어야 합니다.

2. 외부 자료와 개인 생각을 구분한다

개인 지식 Wiki에는 다음 내용이 함께 들어갈 수 있습니다.

  • 저자의 주장
  • 연구 결과
  • LLM의 종합
  • 나의 경험
  • 나의 해석
  • 아직 검증하지 않은 가설

이들을 구분하지 않으면 나중에 어떤 내용이 사실이고 어떤 내용이 개인적인 판단인지 알기 어렵습니다.

예:

## 원본의 주장

환경을 바꾸면 원하는 행동을 시작하기 쉬워질 수 있다.

## 나의 경험

휴대전화를 다른 방에 두었을 때
오전 글쓰기 시간이 늘어났다.

## 나의 해석

물리적 거리가 집중 시작에 영향을 준 것으로 보인다.

## 검토 필요

다른 요인도 영향을 주었을 가능성이 있으므로
반복 실험이 필요하다.

3. 출처 연결이 필요하다

Wiki 페이지에 근거가 없으면 시간이 지난 뒤 내용을 검증하기 어렵습니다.

예:

# 습관 형성

## 핵심 주장

습관 형성에서는 목표보다
반복 가능한 행동과 환경 설계가 중요할 수 있다.

## 관련 자료

- [[sources/아주-작은-습관의-힘]]
- [[sources/습관에-관한-강의-노트]]

## 개인 기록

- [[reflections/아침-루틴-실험]]

Wiki 내부 링크만으로는 원본의 어느 부분을 근거로 했는지 부족할 수 있습니다.

필요한 경우 페이지 안에 다음 정보를 추가합니다.

  • 원본 파일 경로
  • 장 또는 페이지
  • 문단 또는 시간 정보
  • 직접 인용과 요약의 구분
  • 수집 날짜

4. LLM이 원본을 수정하지 않도록 한다

Raw Sources의 불변성은 개인 지식 관리에서도 중요합니다.

원본이 수정되면 다음 문제가 생길 수 있습니다.

  • 저자의 실제 주장과 LLM의 수정 내용이 섞임
  • 과거에 내가 작성한 생각이 현재 관점으로 덮어써짐
  • Wiki의 근거를 다시 확인하기 어려워짐
  • 해석이 변한 과정을 추적할 수 없음

잘못된 내용이 발견되면 Raw Sources를 수정하기보다 Wiki 페이지에서 다음과 같이 처리합니다.

## 정정

이 페이지의 이전 설명은 원본의 의미를 지나치게 확대했다.

## 수정된 설명

원본은 모든 상황에 적용되는 일반 법칙을 주장한 것이 아니라,
특정 조건에서 나타날 수 있는 경향을 설명한다.

5. 자동 생성 페이지가 항상 정확한 것은 아니다

LLM은 다음과 같은 실수를 할 수 있습니다.

  • 서로 다른 개념을 같은 것으로 합침
  • 비슷한 인물을 하나의 인물로 잘못 연결함
  • 출처에 없는 내용을 추론하여 추가함
  • 오래된 정보를 현재 사실처럼 유지함
  • 같은 개념의 중복 페이지를 생성함
  • 링크는 연결했지만 관계를 잘못 설명함
  • 개인적인 경험을 일반적인 사실처럼 표현함
  • 한 저자의 주장을 다른 저자의 주장으로 잘못 표시함
  • 과거의 생각과 현재의 생각을 구분하지 않음

따라서 Ingest와 Lint는 단순한 부가 기능이 아니라 Wiki를 신뢰할 수 있게 유지하는 핵심 절차입니다.

6. 모든 질문을 Wiki에 저장하지 않는다

대화 기록을 모두 저장하면 Wiki가 빠르게 복잡해질 수 있습니다.

저장 여부는 다음 질문으로 판단할 수 있습니다.

이 결과를 한 달 뒤에도 다시 참고할 가능성이 있는가?

여러 자료를 연결한 새로운 내용인가?

기존 Wiki의 이해를 바꾸는가?

다른 질문에 다시 활용할 수 있는가?

장기간 추적할 가치가 있는가?

저장하기 좋은 것:

  • 중요한 개념 비교
  • 여러 자료를 종합한 분석
  • 반복해서 참고할 설명
  • 나의 생각이 변화한 과정
  • 실제로 수행한 실험과 결과
  • 새로운 개념 정의
  • 기존 지식을 수정하는 발견
  • 장기간 추적할 질문
  • 프로젝트에서 반복해서 사용할 원칙

저장하지 않아도 되는 것:

  • 단순 확인 질문
  • 일회성 계산
  • 잠깐 필요한 번역
  • 형식만 바꾸는 작업
  • 이미 존재하는 내용의 반복
  • 근거가 없는 즉흥적 추측
  • 다시 참고할 가능성이 낮은 답변

7. 개인 자료의 민감성을 고려한다

개인 지식 Wiki에는 건강, 감정, 관계, 업무, 재정과 같은 민감한 내용이 들어갈 수 있습니다.

자료를 추가하기 전에 다음을 확인합니다.

  • 외부 LLM 서비스에 전송해도 되는 자료인가
  • 타인의 개인정보가 포함되어 있는가
  • 회사나 조직의 기밀 정보가 포함되어 있는가
  • 건강이나 재정 관련 기록을 별도로 관리해야 하는가
  • 공개 저장소에 올려도 되는 내용인가
  • Git 기록에 남겨도 되는 정보인가

필요한 경우 다음과 같이 자료를 분리합니다.

personal-llm-wiki/
├─ raw-public/
├─ raw-private/
├─ wiki-public/
└─ wiki-private/

또는 민감한 영역은 별도의 Wiki로 관리할 수 있습니다.

8. 처음부터 거대한 구조를 만들지 않는다

처음부터 다음과 같은 구조를 모두 만들 필요는 없습니다.

concepts/
people/
books/
articles/
questions/
reflections/
projects/
comparisons/
synthesis/
timelines/
experiments/

초기에는 실제로 필요한 페이지 유형만 사용합니다.

예:

wiki/
├─ index.md
├─ log.md
├─ sources/
└─ concepts/

사용하면서 비교 분석이 많아지면 comparisons/를 추가하고, 개인 실험을 기록하게 되면 reflections/ 또는 experiments/를 추가합니다.

구조는 자료보다 먼저 완성되는 것이 아니라, 자료와 질문이 쌓이면서 함께 발전해야 합니다.

📚 LLM Wiki는 처음부터 크게 만들 필요가 없습니다. 작은 영역 하나로 시작해 Ingest → Query → Lint를 반복하세요.
