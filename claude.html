WEB

모델 라인업: 일에 맞춰 고르기

Claude는 크기와 성격이 다른 여러 모델로 나뉩니다. 무조건 가장 큰 모델이 좋은 게 아니라, 일의 난이도와 속도에 맞춰 고르면 됩니다.

등급성격잘 맞는 일고려할 점
Fable최상위 모델아주 어려운 추론, 오래 걸리는 복잡한 에이전트 작업별도 사용 요금 부과. 대부분의 일은 Opus로 충분
Opus강력한 상위 모델복잡한 분석, 긴 작업, 어려운 판단, 대규모 코드 작업느리고 사용량을 많이 씀
Sonnet성능과 속도의 균형일상 업무 대부분: 문서 작성, 자료 정리, 일반 코딩무난한 기본 선택
Haiku가장 빠르고 가벼움단순 분류, 짧은 요약, 많은 양의 반복 처리깊은 추론은 약함
💡 바꾸는 법
입력창 아래의 모델 선택 메뉴에서 바꿉니다. Code 탭에서는 같은 자리에서 생각의 깊이(effort)도 고를 수 있어요. 깊게 생각할수록 정확하지만 느려집니다.
💰 Fable은 별도 요금
Fable은 요금제 기본 사용량에 포함되지 않고 별도 사용 요금(추가 사용량)이 부과돼요. Pro 요금제는 처음부터 별도 결제이고, Max 같은 상위 요금제도 정해진 한도를 넘으면 별도 요금이 붙습니다. 모델 메뉴에서 무심코 고르지 않도록 주의하세요.

※ 2026년 11월 기준으로는 Fable 5.1, Opus 5.5 · Sonnet 5.5 · Haiku 5.5가 최신이에요. 라인업과 요금 조건은 계속 바뀌니 모델 선택 메뉴와 요금제 안내에서 확인하세요.

토큰과 컨텍스트

TOKEN

토큰

AI가 글을 처리하는 단위예요. 글자를 잘게 나눈 조각이라고 보면 됩니다. 읽는 양과 쓰는 양 모두 토큰으로 계산되고, 사용량 한도도 토큰 기준이에요.

CONTEXT

컨텍스트

AI가 한 번에 보고 참고하는 이 대화의 정보 전체예요. 대화 내용, 읽은 파일, 지침, 도구 실행 결과가 모두 들어갑니다. 담을 수 있는 양(컨텍스트 창)에는 한계가 있어요.

컨텍스트를 아끼는 습관이유
큰 PDF는 필요한 구간만799쪽 통계 PDF 전체보다 관련 20쪽이 더 빠르고 정확해요
주제가 바뀌면 새 대화지난 주제의 내용이 남아 판단을 흐립니다
오래 쉰 대화도 새 세션캐시가 60분 뒤 사라져, 이어서 보내면 앞 대화 전체를 다시 읽느라 토큰을 많이 써요
반복 기준은 파일로매번 붙여넣지 말고 CLAUDE.md와 Skill에 저장해요
컨텍스트 표시로 확인Code 탭 오른쪽 패널의 컨텍스트에서 지금 대화가 얼마나 찼는지, 무엇이 자리를 차지하는지 볼 수 있어요
📌 핵심
필요 없는 내용이 많이 들어갈수록 정작 중요한 기준이 뒤로 밀립니다.

프롬프트 캐싱: 이어서 하면 아끼고, 오래 쉬면 다시 써요

Claude는 메시지를 보낼 때마다 앞의 대화 전체를 다시 읽고 답해요. 매번 처음부터 읽으면 토큰이 많이 들기 때문에, 방금 읽고 계산한 결과를 서버에 잠시 보관해 두고 다음 메시지에서 꺼내 씁니다. 이 기능을 프롬프트 캐싱(Prompt Caching), 보관된 결과를 프롬프트 캐시(줄여서 캐시)라고 불러요. 캐시에서 꺼내 읽는 양은 새로 읽는 것보다 훨씬 적게 계산돼요.

📌 기억이 아니라 책갈피
내용을 외운 게 아니라 읽던 책에 끼워 둔 책갈피예요. 다시 펼치면 바로 이어 읽지만, 시간이 지나면 빠집니다. 60분 안에 이어서 보낸다고 답변이 더 좋아지는 건 아니고, 토큰을 덜 쓸 뿐이에요.
메시지 보냄→앞 대화는 캐시에서 꺼내 읽음→60분 타이머 다시 시작→60분간 아무것도 안 보내면 캐시 삭제
상황캐시는토큰은
대화를 계속 이어갈 때보낼 때마다 60분 타이머가 다시 시작돼 유지앞 내용은 캐시에서 꺼내 적게 씀
60분 넘게 아무것도 안 보냈을 때사라짐다음 메시지에서 앞 대화 전체를 다시 읽어 처음처럼 다시 씀
대화 중간에 모델을 바꿀 때모델마다 캐시가 따로라 새로 만듦바꾼 직후 한 번은 앞 대화 전체를 다시 읽음
⏱️ 권장
마지막으로 보낸 뒤 시간이 오래 지난 대화는 이어 쓰지 말고 무조건 새 세션으로 열어서 하세요. 이어서 할 내용은 CLAUDE.md나 정리 파일에 남겨 두고, 새 세션에서 그 파일을 읽게 하면 됩니다. 모델도 대화 중간에 바꾸기보다 시작할 때 정해 두는 편이 좋아요.

※ Code 탭을 구독 요금제로 쓸 때 기준이에요. 유지 시간은 요금제와 사용 방식에 따라 달라질 수 있어요.

PART 02

챗봇에서 에이전트로

"질문하는 법"이 아니라 "일을 맡기는 법". 늘 쓰던 Claude Chat과 Claude Code에 같은 일을 시켜보면서 차이를 살펴봅니다.

Claude에는 Chat과 Code가 있어요

Claude Desktop 앱에는 Chat과 Code 탭이 있어요. 같은 Claude지만 일하는 방식이 달라서, Chat은 챗봇처럼, Code는 에이전트처럼 일합니다.

CHAT · 챗봇

💬 대화하며 답을 받는 곳

질문하면 대화창에 답을 써줘요. 요약, 초안, 아이디어 정리처럼 답을 받는 일에 써요.

CODE · 에이전트

🤖 내 PC 폴더에서 일을 맡기는 곳

작업 폴더를 열고 일을 맡기면 Claude가 파일을 직접 읽고, 만들고, 정리해요. 일을 끝내야 하는 작업에 써요.

그럼 챗봇과 에이전트는 무엇이 다를까요? 비유와 예시로 차근차근 살펴볼게요.

비유로 이해하기

챗봇

💬 레시피를 알려주는 친구

"김치찌개 어떻게 끓여?"라고 물으면 순서를 친절하게 알려줘요. 하지만 장을 보고, 재료를 썰고, 끓이는 건 내가 해야 합니다.

에이전트

🧑‍🍳 우리 집 부엌에 온 요리사

"저녁으로 김치찌개 해줘"라고 하면 냉장고를 열어 재료를 확인하고, 직접 끓이고, 간을 보고 고쳐서 완성된 찌개를 내놓아요.

📌 핵심
챗봇은 어떻게 하는지 알려주고, 에이전트는 직접 해서 끝내줍니다. 그래서 사람이 할 일이 "직접 하기"에서 "원하는 것을 말하고 결과를 확인하기"로 바뀌어요.

이제 같은 일을 Chat(챗봇)과 Code(에이전트)에 똑같이 시켜볼게요.

예시 ②에서 Claude Code는 한 번 답하고 멈추지 않았어요. 목표를 받고, 계획을 세우고, 도구로 실행하고, 결과를 확인했습니다. 잘못된 게 있으면 고치고 다시 확인해요. 이렇게 일이 끝날 때까지 도는 순환을 작업 루프라고 부릅니다.

중요한 건 "AI가 똑똑한가"가 아니라 "에이전트가 어떤 도구를 쓸 수 있는가"예요. 연결되지 않은 메일함은 아무리 좋은 모델도 읽을 수 없습니다.

답은 MCP와 커넥터예요

MCP(Model Context Protocol)는 AI가 외부 도구와 데이터를 일관된 방식으로 연결하도록 돕는 표준이에요. Claude 앱에서는 이 연결을 커넥터라는 형태로 설정합니다. 연결된 도구는 대화 중에 부를 수 있는 업무 기능이 돼요.

MCP host→MCP client→MCP server→Tool
구성 요소뜻예
MCP host도구를 쓰는 AI 앱Claude 웹, Claude Desktop
MCP clienthost 안에서 server와 통신하는 연결부커넥터 연결 설정
MCP server실제 업무 기능을 제공하는 쪽Slack, Gmail, Calendar, Notion
Tool호출할 수 있는 개별 기능메일 읽기, 메시지 보내기, 일정 생성
📌 핵심
커넥터는 에이전트에게 외부 도구를 열어주는 연결 방식, MCP는 그 연결이 안정적으로 작동하게 하는 표준 규격입니다.

커넥터는 내가 승인한 범위만 열어요

단계하는 일여기서 확인할 것
01 앱 선택어떤 외부 앱을 연결할지 결정지금 정말 필요한 도구인지
02 계정 선택어떤 계정으로 연결할지 확인회사 계정인지 개인 계정인지
03 권한 확인읽기·쓰기·전송 범위 확인읽기만 필요한데 전송 권한까지 주는 건 아닌지
04 사용 확인실행 전 필요하면 다시 확인전송·생성 직전에 사람이 한 번 더 보는지

커넥터 화면 찾기: 사이드바 사용자 지정 > 커넥터에서 연결 상태를 보고, 연결을 끊거나 다시 연결해요. 대화 중에는 입력창 + 버튼 > 커넥터 > 커넥터 관리로 바로 들어갈 수 있어요. 새 도구는 커넥터 화면에서 커넥터 디렉터리를 열어 찾습니다.

Skill이란? 업무 하나를 맡기는 매뉴얼

Skill은 특정 업무 하나를 어떤 순서로, 어떤 기준으로, 어디까지 처리할지 적어 둔 업무 매뉴얼이에요. 폴더 하나에 SKILL.md 파일을 넣어 만들고, 필요하면 양식·참고 문서·스크립트도 함께 넣습니다. Claude는 요청을 보고 맞는 Skill이 있으면 그 매뉴얼을 꺼내 그대로 따라 일해요.

WHAT

업무 하나 단위

"아침 브리핑 만들기", "주간 보고서 쓰기"처럼 한 가지 업무를 다뤄요.

WHEN

필요할 때만

평소에는 이름과 설명만 알고 있다가, 요청이 맞을 때 본문을 펼쳐요.

WHERE

어디서든

한 번 설치하면 폴더나 대화가 바뀌어도 같은 방식으로 쓸 수 있어요.
