여기서 HTML은 크롬 같은 브라우저에서 바로 열리는 화면 파일이에요. 파일 하나를 더블클릭하면 화면이 뜨고, 메신저로 그 파일만 보내도 상대방 PC에서 똑같이 열립니다.

오늘은 화면부터 만듭니다

긴 정의보다 화면을 먼저 만드는 이유

보통 데이터 작업은 정리 → 분석 → 보고서 작성 순서로 진행됩니다. 그런데 AI에게 일을 맡길 때 이 순서를 그대로 따라가면 시간이 많이 걸려요. 첫 화면이 나오기 전까지는 무엇을 고쳐야 할지도 알 수 없거든요.

그래서 이번 교시는 순서를 바꿉니다. 정제된 데이터를 일단 HTML 화면으로 바꾼 뒤, 결과를 보면서 요청을 고칩니다.

이 방식의 장점은 분명해요.

  • 데이터에 어떤 열이 더 필요한지 화면에서 바로 보입니다.
  • 어떤 지표가 첫 화면에 올라가야 하는지 빠르게 판단할 수 있습니다.
  • 차트와 표가 업무 질문에 맞는지 눈으로 확인할 수 있습니다.
  • 수정 요청을 말로 설명하기 훨씬 쉬워집니다.

표에 보이는 열 이름 중 두 개는 지금 짚고 가면 좋아요. ROAS는 광고비 대비 매출 비율입니다. 광고비 1원으로 매출을 몇 원 만들었는지 보는 지표예요. 이번 실습 데이터의 열 이름은 ROAS(배수)이고 값은 전부 배수로 들어 있어서, 4.2면 광고비 1원으로 매출 4.2원을 만들었다는 뜻입니다. 퍼센트로 바꿔 읽지 않아요. SKU는 재고 관리 단위로, 제품을 용량·옵션까지 구분한 최소 판매 단위예요. 같은 콜라겐 제품이라도 30포짜리와 60포짜리는 서로 다른 SKU입니다.

이 데이터는 2026년 6월 한 달치예요. 전월 데이터가 없어서 "전월 대비" 비교는 할 수 없고, 기간 비교는 6월 상반기(1~15일)와 하반기(16~30일)로 나눠서 봅니다.

두 파일은 반드시 같이 읽혀야 의미가 생겨요. 본문 데이터만 있으면 숫자는 보이지만 그 제품이 무엇인지 알 수 없고, 제품마스터만 있으면 기준은 있는데 현재 상태가 없습니다. 예를 들어 "재고 320개"라는 숫자는 그 SKU의 안전재고가 500개라는 기준과 만나야 "재고 부족"이라는 신호가 되죠.

# 뉴트리원 대시보드 기준

## 화면 구성
- 첫 화면 상단에 필터 바 고정 (기간, 채널, 브랜드)
- KPI 카드는 매출액, 광고비, ROAS, 위험 신호 건수 순서로 가로 배치
- 위험 신호 영역은 차트보다 위에 배치

## 표기 규칙
- ROAS는 배수로만 표기 (예: 4.2배). 퍼센트 변환 금지
- 금액은 억·만 단위 한글 표기 (예: 3.8억, 4,920만)
- 위험 신호는 주황 한 가지로만 표시하고 "확인필요" 배지를 붙인다

오늘의 작업 방향 — 이미지 생성이 아니라 상세페이지 시안

"예쁜 이미지 만들기"가 목표가 아니에요

상세페이지 디자인은 예쁜 이미지를 길게 이어 붙이는 일이 아닙니다. 고객이 제품을 처음 보고, 왜 필요한지 이해하고, 믿을 수 있는 근거를 확인한 뒤, 구매 직전의 마지막 불안을 줄이는 흐름을 설계하는 일이에요.

그래서 오늘은 이미지를 새로 그리는 데 시간을 쓰지 않습니다. 이미 확보한 제품 자산을 그대로 두고, 섹션 순서와 카피, 정보 위계를 빠르게 잡는 것에 집중해요.

단계하는 일왜 이렇게 하나요
01. 제품 이미지는 유지이미 확보한 자산을 기준으로 작업촬영·합성보다 이미 있는 자산이 정확하고 빠릅니다
02. 상세페이지 구조화섹션과 정보 순서를 먼저 정리화면을 그리기 전에 무엇을 어떤 순서로 보여줄지 정합니다
03. 구성안 작성디자인팀과 논의할 문서 생성말로 설명하는 대신 문서로 넘겨 오해를 줄입니다
04. HTML 시안카피 길이와 배치를 화면으로 확인글자 수와 여백은 화면으로 봐야 판단이 됩니다

AI가 가장 자연스럽게 만들어내는 위험한 문장

AI에게 "상세페이지 만들어줘"라고 하면 결과가 흔들리기 쉽습니다. 이유는 단순해요. 생성 모델은 빈칸을 채우려고 합니다. 근거 자료에 없는 내용이라도, 문맥상 자연스러운 문장이면 만들어냅니다.

건강기능식품에서는 이 성질이 그대로 리스크가 됩니다. AI가 만들어낸 아래 문장들은 전부 문법적으로 자연스럽지만, 상세페이지에 그대로 올리면 문제가 될 수 있어요.

- 배경색, 포인트 색, 글자 크기 비율은 pattern_report.md 에서 관찰한 값을 써줘

HTML은 화면일 뿐이라 그대로는 채널에 올릴 수 없어요. 이미지 파일로 바꿔야 합니다. 가장 쉬운 방법은 Claude Code에게 캡처까지 시키는 것입니다.

왜 이미지 생성 도구 대신 HTML로 만드나요

간단합니다. 글자가 정확하게 나오고, 규격을 픽셀 단위로 맞출 수 있고, 문구만 바꿔 재사용할 수 있어서예요. 이미지 생성 모델은 아직 한글 글자를 자주 깨뜨리고, 요청한 픽셀 크기를 정확히 지키지 못합니다.

다만 이 방식에도 분명한 한계가 있어요. 솔직하게 알아두고 쓰셔야 합니다.

HTML로 잘 되는 것HTML로는 안 되는 것
글자 중심 배너, 프로모션 카드, 가격·혜택 표기사진 합성과 리터칭

📌 핵심

Skill은 AI를 똑똑하게 만드는 파일이 아니라, 매번 같은 설명을 반복하지 않게 해주는 파일입니다.

2교시에서는 제품 상세페이지처럼 사람이 보는 결과물을 만들었어요. 이번 교시에서는 사람이 보는 화면이 아니라, 내 PC에서 실제로 돌아가는 프로그램을 만듭니다.

채널별 상품·가격·리뷰 RAW 엑셀을 읽어 하나의 결과 파일로 합쳐주는 탭형 업무 도구를 만들고, 마지막에는 더블클릭으로 실행되는 윈도우 실행 파일(exe)까지 뽑아봅니다.

코드를 외우는 시간이 아니라, 업무를 작게 잘라서 AI에게 맡기는 감각을 익히는 시간이에요.

업무 도구를 만드는 바이브코딩

바이브코딩은 코드를 외우는 일이 아니에요

바이브코딩이란 코드를 직접 타이핑하는 대신, 자연어로 원하는 것을 설명해서 AI와 함께 실행 가능한 프로그램을 만드는 방식입니다. 여기서 핵심은 프롬프트를 길게 쓰는 게 아니라 업무 목적을 작게 자르는 것이에요.

업무 도구를 만드는 흐름은 다섯 단계로 정리됩니다.

단계하는 일이번 교시에서는
01. 업무 목적무엇을 줄이고 싶은지 정의합니다채널별 RAW 엑셀을 손으로 합치는 시간 줄이기
02. 작은 기능파일 읽기부터 시작합니다엑셀 시트를 읽고 미리보기를 띄우는 것부터
03. 도구 형태exe, 확장프로그램, 웹사이트 중 고릅니다내 PC 파일을 직접 고르는 exe 프로그램
04. 실행 테스트결과 파일을 기준으로 검증합니다combined_result.xlsx가 제대로 나왔는지 확인
05. 반복 수정오류와 요구를 좁혀서 전달합니다오류가 난 탭만 지정해서 다시 요청
📌 핵심
프로그램을 크게 잡으면 끝나지 않고, 작게 자르면 오늘 안에 돌아갑니다.

터미널을 연 뒤 아래 명령을 그대로 입력하고 Enter를 누르세요.

python --version

실습 2-A: 실제로 쓰는 패키지만 남기기

패키지란 프로그램이 빌려 쓰는 기능 묶음이에요. 엑셀을 읽는 기능, 화면을 그리는 기능처럼요. 쓰지 않는 패키지가 섞여 들어가면 exe 용량이 커지고 빌드도 자주 실패합니다.

작업 폴더에는 requirements_참고.txt 가 들어 있어요. 흔히 쓰는 패키지를 모아둔 참고본이라, 이번 실습에서는 여기서 실제로 쓰는 것만 골라내 최소 구성으로 줄입니다.

단어뜻

가상환경이 프로젝트에서만 쓸 부품을 따로 담아두는 상자예요. 상자 안에만 설치하면 PC의 다른 프로그램이 영향을 받지 않습니다

실습 2-B: PyInstaller 빌드 요청

PyInstaller는 Python 코드를 하나의 실행 파일로 묶어주는 도구입니다. onefile 모드는 필요한 것을 전부 한 파일 안에 넣는 방식이라, 파일 하나만 전달하면 돼요. 패키지 정리가 끝난 뒤 최소 구성으로 단일 exe를 먼저 확인합니다.

아래 프롬프트에 나오는 spec 파일은 빌드 설명서예요. 어떤 파일을 함께 넣을지, 실행 파일 이름은 무엇으로 할지를 적어둔 메모라서, 다음에 다시 빌드할 때 이 파일만 있으면 같은 결과가 나옵니다.

✍️ 입력할 프롬프트
product-data-tool 프로젝트를 PyInstaller로 빌드하는 최소 구성을 만들어줘.

조건:
- onefile 모드 우선
- 실제 필요한 데이터 파일만 포함
- product_data_tool.spec 생성
- 빌드 명령과 dist 폴더 확인 방법 작성
- 빌드 후 exe 실행 테스트 절차 작성

빌드가 끝나면 실행 파일은 프로젝트 폴더 안의 dist/ 폴더에 생깁니다.

product-data-tool/
└─ dist/
   └─ product_data_tool.exe
💡 TIP

수집보다 먼저 제한을 정합니다

하지 않을 일 다섯 가지, 할 일 한 가지

브라우저 확장 프로그램은 꽤 강력한 도구예요. 그래서 "무엇을 할 수 있는가"보다 "무엇을 하지 않을 것인가" 를 먼저 정하고 시작합니다. 교육용 확장은 대량 수집기가 아니라, 현재 페이지 정보를 구조화하는 업무 보조 도구입니다.

이 표가 바로 다음 단계에서 입력할 프롬프트의 제한 다섯 줄과 글자 그대로 이어집니다.

구분기준구체적으로는
❌로그인 우회 금지권한 없는 화면에 접근하지 않습니다
❌차단 우회 금지탐지 회피와 반복 호출을 하지 않습니다
❌숨겨진 API 호출 금지화면 밖 데이터를 몰래 불러오지 않습니다
❌자동 순회 금지여러 페이지를 일괄 방문하지 않습니다
❌개인정보 수집 금지상품 공개 정보만 대상으로 합니다
⭐현재 페이지 기준화면에 보이는 공개 정보만 구조화합니다

여기서 API라는 말이 나왔는데, API는 프로그램끼리 데이터를 주고받는 통로를 말해요. 화면에는 안 보이지만 뒤에서 데이터가 오가는 경로가 있는데, 이번 실습에서는 그 경로를 건드리지 않고 눈에 보이는 화면 텍스트만 다룹니다. 같이 나오는 호출은 그 통로로 "이 데이터 좀 줘"라고 요청을 보내는 일을 말합니다.

왜 제한을 먼저 적어야 하나요

단순히 조심하자는 뜻이 아닙니다. 업무 도구의 목적이 무리한 대량 수집이 아니라, 사람이 이미 보고 있는 화면을 더 빠르게 정리하는 것이기 때문이에요.

제한을 먼저 적으면 AI에게 요청할 때도 결과가 달라집니다. 제한 없이 "긁어와줘"라고 하면 AI는 자동 순회나 API 호출까지 시도하는 코드를 만들 수 있어요. 제한을 함께 적으면 업무에서 그대로 쓸 수 있는 안전한 형태로 나옵니다.

여기서 크롤러는 웹사이트를 자동으로 돌아다니며 정보를 대량으로 긁어오는 프로그램이에요. 오늘 만드는 건 그게 아닙니다.

실습 1-C: 확장 프로그램 초안 생성 요청

기능:

- 팝업 버튼: 현재 화면 수집, 스크롤 후 수집, 엑셀 다운로드
- 기본 컬럼: 제목, 가격, 리뷰수, 할인율, 이미지 URL, 상세 URL, 수집 시점
- 사이트별 추출 규칙을 나중에 추가할 수 있도록 extractor 구조 분리
- 페이지에서 찾지 못한 항목은 빈 값으로 두고 이유 표시
- 결과 미리보기와 XLSX 다운로드

제한:
- 로그인 우회 금지
- 차단 우회 금지
- 숨겨진 API 호출 금지
- 여러 페이지 자동 순회 금지
- 개인정보 수집 금지

구현 후 설치 방법, 테스트 방법, 동작하지 않을 때 확인할 선택자 목록을 README.md에 정리해줘.

✅ 이렇게 나오면 성공이에요

  • browser-data-exporter/ 폴더가 생기고 그 안에 설정 파일과 화면 파일들, README.md 가 들어 있습니다
  • 팝업에 버튼 세 개(현재 화면 수집 / 스크롤 후 수집 / 엑셀 다운로드)가 들어가 있습니다
  • README.md 에 설치 방법과 "동작하지 않을 때 확인할 선택자 목록" 이 적혀 있습니다
  • 자동 순회나 숨겨진 API 호출 코드가 들어가 있지 않습니다

여기서 manifest v3는 크롬 확장 프로그램의 최신 설정 규격을 말해요. 지금 크롬에 새로 올릴 수 있는 확장은 이 규격을 따라야 합니다. 프롬프트에 이 한 줄을 넣지 않으면 예전 규격으로 만들어져 로드가 안 될 수 있으니 꼭 적어주세요.

프롬프트에 나오는 extractor는 "이 사이트에서는 어느 자리를 읽으면 되는지" 적어둔 추출 규칙 파일을 말해요. 사이트마다 하나씩 두면, 나중에 다른 사이트를 추가할 때 이 파일만 새로 만들면 됩니다.

실습 1-D: 만들어진 폴더 확인

AI가 작업을 끝냈다면, 대화 요약만 믿지 말고 파일 탐색기(Mac은 Finder)에서 직접 확인합니다. 아래 파일들이 있어야 해요.

확인할 것기준
manifest.json 이 있는가이 파일이 없으면 크롬이 확장으로 인식하지 못합니다
popup.html 과 popup.js 가 있는가버튼 화면과 동작이 만들어졌는지 확인
content.js 가 있는가페이지를 읽는 부분이 있는지 확인

폴더 이름이 browser-data-exporter 인가다음 단계에서 이 폴더를 선택합니다
폴더 하나에 파일 다섯 개, 각각 무슨 일을 하나요

눈앞에 진짜 파일이 있으니 하나씩 열어보면서 역할을 읽어봅시다. 폴더는 이렇게 생겼을 거예요.

browser-data-exporter/
├─ manifest.json
├─ popup.html
├─ popup.js
├─ content.js
├─ lib/
│  └─ site-extractors/
└─ README.md

각 파일의 역할은 단순하게 이해하면 됩니다.

파일구분역할

popup.jsACTION버튼 클릭과 결과 표시를 연결

manifest.json 을 열어보면 중괄호와 따옴표가 가득한 형식이 보일 거예요. 이게 JSON입니다. JSON은 컴퓨터가 읽는 설정 표기법이에요. 쉼표나 따옴표 하나만 빠져도 전체가 안 읽힙니다.

💡 TIP
lib/site-extractors 폴더가 지금은 비어 있거나 쿠팡 규칙 하나만 들어 있어도 괜찮아요. 이 폴더는 나중에 다른 사이트로 넓힐 때 쓰는 자리인데, 이 시간 마지막에 다시 다룹니다.

실습 2. 만든 확장 프로그램을 크롬에 로드하기

실습 목표

확장 프로그램은 처음부터 웹스토어에 올리지 않아요. 배포 전에는 압축해제된 폴더를 개발자 모드로 직접 로드해서 테스트합니다. 처음 해보면 낯선 화면이라 단계를 아주 잘게 나눠서 진행할게요.

말이 두 개 나왔죠. 웹스토어는 확장 프로그램을 누구나 받아갈 수 있게 공개해두는 브라우저 공식 장터예요. 그리고 배포는 내가 만든 걸 다른 사람도 쓸 수 있게 내보내는 일을 말합니다. 오늘은 배포를 하지 않고, 내 PC에서만 돌려봅니다.

⚠️ 주의
중요: 아래 단계는 한 번에 몰아서 하지 말고, 한 단계씩 화면을 확인하면서 진행하세요. 어디서 막혔는지 알아야 뒤에 나오는 확인 표를 쓸 수 있습니다.

Chrome으로 만들고 Edge에서도 씁니다

오늘 실습 기준 브라우저는 Chrome입니다. Microsoft Edge도 Chrome과 같은 Chromium 계열 브라우저라서 같은 확장 구조를 그대로 사용할 수 있습니다. 여기서 Chromium은 브라우저의 속 엔진 이름이에요. Chrome과 Edge는 속이 같은 엔진으로 만들어져 있어요. 그래서 한쪽에서 만든 확장이 다른 쪽에서도 그대로 돌아갑니다.

즉, 오늘 배우는 건 브라우저 하나에만 갇힌 지식이 아니라 브라우저 위에서 업무 도구를 설계하는 방식입니다. 아래 단계를 Edge에서 할 때는 이 표대로 바꿔 읽으시면 돼요.

단계ChromeEdge
관리 화면 열기chrome://extensionsedge://extensions
개발자 모드오른쪽 위 토글왼쪽 아래 토글
폴더 로드압축해제된 확장 프로그램 로드압축 풀린 항목 로드
선택할 폴더manifest.json 이 들어 있는 폴더동일

버튼 이름과 위치만 조금 다르고, 선택하는 폴더와 확인 방식은 완전히 같습니다. 회사 PC에서 크롬 개발자 모드가 막혀 있다면 Edge로 진행해도 됩니다.

💡 TIP
공식 문서를 확인하고 싶다면 Chrome은 확장 프로그램 시작 가이드, Edge는 Edge 확장 개발 문서를 보시면 됩니다. 오늘 쓰는 방식은 두 문서 모두에 나오는 표준 절차예요.
실습 2-A: 확장 프로그램 관리 화면 열기

두 가지 방법 중 편한 쪽을 쓰세요.

  1. 메뉴로 열기 — 크롬 오른쪽 위 점 세 개 버튼 클릭 → 확장 프로그램 → 확장 프로그램 관리
  2. 주소창으로 열기 — 주소창에 chrome://extensions 를 입력하고 Enter

확인 포인트: 화면 왼쪽 위에 확장 프로그램이라는 제목이 보이면 제대로 들어온 겁니다.

실습 2-B: 개발자 모드 켜기
  1. 같은 화면 오른쪽 위에 개발자 모드 토글 스위치가 있습니다.
  2. 이 스위치를 켭니다.
  3. 켜지면 화면 왼쪽 위에 버튼 세 개가 새로 나타납니다.
압축해제된 확장 프로그램 로드   |   확장 프로그램 압축   |   업데이트

확인 포인트: 이 버튼 세 개가 안 보이면 토글이 아직 안 켜진 상태예요. 다음 단계로 넘어가지 마세요.

실습 2-C: 압축해제된 확장 프로그램 로드 클릭
  1. 왼쪽 위 압축해제된 확장 프로그램 로드 버튼을 클릭합니다.
  2. 폴더를 고르는 창이 열립니다.

여기서 헷갈리는 분이 많은데, 파일이 아니라 폴더를 고르는 창입니다. 파일 목록이 안 보인다고 당황하지 않으셔도 돼요.

실습 2-D: 어느 폴더를 선택할지 정확히 알기

이 단계가 로드 실패의 가장 큰 원인입니다. 천천히 보세요.

  1. 폴더 선택 창에서 실습 폴더까지 이동합니다.
  2. browser-data-exporter 폴더를 더블클릭해서 안으로 들어갑니다.
  3. 폴더 안에 manifest.json 이 바로 보이는지 확인합니다.
  4. 그 상태에서 폴더 선택 버튼을 누릅니다.
올바른 선택 위치
2일차_실습자료/4교시_브라우저확장프로그램/AI마스터클래스_2일차/
└─ browser-data-exporter/   ← 이 폴더를 선택
   ├─ manifest.json          ← 폴더 안에 바로 보여야 합니다
   ├─ popup.html
   └─ ...
💡 TIP
manifest.json 파일 자체를 선택하는 게 아니라, 그 파일이 들어 있는 폴더를 선택하는 거예요. 한 단계 위 폴더를 선택하면 로드에 실패합니다.

확장 폴더가 아직 만들어지지 않았거나 로드가 계속 실패한다면, 실습자료에 들어 있는 완성본을 대신 써도 됩니다. 4교시_브라우저확장프로그램/참고_완성본_browser-data-exporter 폴더를 그대로 선택해서 로드하세요. 안에 manifest.json, popup.html, popup.js, content.js, README.md, lib/site-extractors/ 가 모두 들어 있어서 바로 동작합니다.

  1. 주소창 오른쪽의 퍼즐 조각 아이콘을 클릭합니다.

실습 2-G: 코드를 고친 뒤에는 반드시 새로고침

AI에게 코드를 수정시킨 뒤 "왜 안 바뀌지?" 하는 경우가 자주 나옵니다. 크롬은 폴더 내용이 바뀌어도 자동으로 반영하지 않아요.

  1. chrome://extensions 화면으로 갑니다.
  2. 확장 카드의 새로고침(↻) 버튼을 클릭합니다.
  3. 테스트 중이던 웹페이지도 F5로 새로고침합니다.
📌 핵심
코드를 고쳤으면 확장 새로고침 + 페이지 새로고침, 두 번입니다.

로드가 안 될 때 확인할 곳

증상별로 확인 지점을 정리했어요. 오류 메시지가 나왔다면 그 문구를 그대로 복사해서 AI에게 붙여넣는 것이 가장 빠른 해결법입니다.

증상가장 흔한 원인확인하고 조치할 것
압축해제된 확장 프로그램 로드 버튼이 안 보임개발자 모드가 꺼져 있음화면 오른쪽 위 개발자 모드 토글을 다시 확인
"Manifest file is missing or unreadable" 오류선택한 폴더 안에 manifest.json 이 없음. 대부분 상위 폴더를 선택한 경우폴더 안으로 한 단계 더 들어가서 manifest.json 이 보이는 위치에서 선택
"Manifest is not valid JSON" 오류설정 파일에 쉼표나 따옴표가 빠진 문법 오류오류 문구를 그대로 AI에게 주고 manifest.json 수정 요청
카드에 빨간 오류 버튼이 뜸스크립트 경로 오타, 권한 표기 오류오류 버튼을 눌러 메시지를 확인하고, 그 내용을 그대로 AI에게 전달
확장 아이콘을 눌러도 팝업이 안 열림popup.html 경로가 틀렸거나 팝업 설정 누락manifest.json 의 action(아이콘 클릭 동작) 항목에 팝업 파일 경로가 맞게 적혀 있는지 확인
팝업은 열리는데 수집 개수가 0content script가 그 페이지에서 함께 실행되지 않음(주입 실패)manifest.json 의 대상 주소 설정에 지금 페이지 주소가 포함되는지 확인 후 페이지 새로고침
수집은 되는데 값이 대부분 비어 있음선택자가 현재 화면 구조와 맞지 않음실습 3-E의 빈 값 원인 구분 절차로 이동
엑셀 다운로드 버튼이 반응 없음다운로드 권한 누락 또는 엑셀 생성 코드 미포함manifest.json 의 permissions(권한 목록)에 downloads가 있는지 확인
코드를 고쳤는데 동작이 그대로임확장을 새로고침하지 않음확장 카드의 새로고침 버튼 → 페이지도 F5
확장이 목록에서 갑자기 사라짐폴더를 옮기거나 폴더명을 바꿈원래 경로로 되돌리거나 새 위치에서 다시 로드
압축(zip) 파일을 선택했더니 안 됨압축을 풀지 않음압축을 해제한 폴더를 선택. 이름 그대로 "압축해제된" 확장입니다
개발자 모드 토글 자체가 비활성회사 PC의 조직 정책으로 차단IT 담당자에게 확인. 개인 계정 크롬이나 Edge로 실습 진행

실습 3. 첫 테스트와 결과 검토

실습 목표

처음부터 여러 페이지를 대상으로 돌리면 문제가 생겼을 때 원인을 찾기 어려워요. 첫 테스트는 검색결과 페이지 하나에서만 진행합니다.

실습 3-A: 테스트 페이지 열기
  1. 크롬 새 탭에서 쿠팡에 접속합니다.
  2. 검색창에 루테인 을 입력하고 검색합니다.
  3. 상품 카드가 여러 개 반복해서 보이는 검색결과 화면인지 확인합니다.
  4. 이 탭을 그대로 둔 채로 확장 아이콘을 클릭해 팝업을 엽니다.
실습 3-B: 현재 화면 수집 (COUNT)
  1. 팝업의 현재 화면 수집 버튼을 클릭합니다.
  2. 수집 개수가 화면에 표시되는지 확인합니다.

수집 개수가 0이면 아직 다음으로 넘어가지 마세요. 위의 로드 실패 확인 표에서 "팝업은 열리는데 수집 개수가 0" 항목을 먼저 확인합니다.

화면 아래쪽 상품까지 잡히지 않는다면 스크롤 후 수집 버튼을 써보세요. 웹페이지는 스크롤해야 상품이 추가로 그려지는 경우가 많거든요.

실습 3-C: 미리보기 확인 (PREVIEW)
  1. 팝업의 미리보기 영역에 상품명이 들어오는지 확인합니다.
  2. 가격, 리뷰 수, 할인율, 이미지 URL이 각각 자리에 맞게 들어왔는지 봅니다.
  3. 비어 있는 칸이 있다면 어느 컬럼인지 메모해둡니다.
실습 3-D: 엑셀 다운로드 (XLSX)
  1. 엑셀 다운로드 버튼을 클릭합니다.
  2. 다운로드 폴더에 수집결과.xlsx 가 저장됩니다.
  3. 파일을 열어 컬럼이 빠짐없이 들어왔는지 확인합니다.
확인 항목기준
COUNT수집 개수가 표시되는가
PREVIEW상품명이 미리보기에 들어오는가
XLSX엑셀을 열었을 때 컬럼 누락이 없는가

이 단계에서 중요한 건 "한 번에 완벽하게 수집되는가"가 아닙니다. 어떤 값이 안정적으로 들어오고, 어떤 값은 확인이 필요한지 구분하는 것이에요.

실습 3-E: 빈 값의 원인을 구분하기

값이 비어 있을 때는 두 가지 경우가 있습니다. 이걸 구분해야 고칠 수 있어요.

경우어떻게 알 수 있나요대응
실제로 페이지에 그 값이 없음화면에서 직접 봐도 할인율이나 리뷰 수 표시가 없음정상. 빈 값으로 두고 누락 사유만 남깁니다
선택자가 맞지 않아서 못 읽음화면에는 값이 보이는데 결과에는 비어 있음해당 항목의 선택자 수정 요청

웹페이지 구조는 계속 바뀝니다. 오늘 잘 동작한 코드도 나중에 실패할 수 있어요. 그래서 처음부터 이렇게 만들어 둡니다.

원칙내용
01. selector 후보한 값에 여러 후보 선택자를 준비합니다
02. 값 없음값을 못 찾아도 오류로 멈추지 않게 만듭니다
03. 이유 표시빈 값과 확인 사유를 함께 기록합니다
04. 샘플 검증업무에 쓰기 전에 사람이 일부를 직접 확인합니다

여기서 선택자(selector) 는 "페이지의 어느 자리에서 값을 읽을지" 알려주는 주소 같은 표시예요. 웹페이지 화면이 개편되면 이 주소가 바뀌어서 값을 못 읽게 됩니다.

값을 못 찾았을 때 아무 값이나 추정해서 넣으면 절대 안 됩니다. 가격 칸은 비워 두고 price_not_found 같은 사유를 남기는 편이 훨씬 안전해요.

✍️ 선택자를 고칠 때 입력할 프롬프트
확장 프로그램 테스트 결과 [할인율] 컬럼이 전부 비어 있어.
화면에는 값이 보이는데 수집이 안 되는 상황이야.

- 해당 항목의 선택자를 여러 후보로 늘려줘
- 후보를 순서대로 시도하고, 다 실패하면 빈 값과 함께 missing_reason에 이유를 남기게 해줘
- 다른 컬럼 동작은 건드리지 마

수정한 파일과 바뀐 부분만 요약해서 알려줘.

✅ 이렇게 나오면 성공이에요

  • 고친 파일 이름과 바뀐 줄만 요약으로 돌아옵니다 (예: lib/site-extractors/coupang.js 의 할인율 선택자 3개 추가)
  • 확장 새로고침 → 페이지 F5 후 다시 수집하면 비어 있던 할인율 칸에 값이 들어옵니다
  • 화면에 정말 할인율이 없는 상품은 여전히 빈 칸이고, missing_reason 에 사유가 적혀 있습니다
  • 상품명·가격처럼 잘 되던 다른 컬럼은 그대로입니다

네 가지가 모두 맞아야 수정이 성공한 거예요. 할인율은 채워졌는데 가격이 비었다면, 고치면서 다른 걸 건드린 겁니다.

실습 3-F: 수집 결과 검토 요청

받은 엑셀 파일을 AI에게 검토시킵니다. 검토 요청은 결과 형식과 누락값 확인에 집중해요.

✍️ 입력할 프롬프트
수집결과.xlsx를 검토해줘.

기준:
- 내가 요청한 컬럼이 결과 파일에 모두 있는지 확인
- 출처 URL과 수집 시점이 없는 행은 확인필요로 표시
- 값이 비어 있는 항목은 임의 추정하지 말고 이유를 남김
- 다른 사이트로 확장할 때 재사용할 컬럼과 사이트별로 바꿀 컬럼을 구분

결과를 표로 정리해줘.

✅ 이렇게 나오면 성공이에요

AI가 아래 같은 검토 표를 돌려줍니다. 숫자는 여러분 파일에 따라 달라집니다.

점검 항목결과판단
요청한 컬럼 8개가 모두 있는가8개 중 8개 존재이상 없음
source(출처 URL)가 비어 있는 행40행 중 3행확인필요
captured_at(수집 시점)이 비어 있는 행0행이상 없음
discount(할인율)이 비어 있는 행40행 중 11행, 사유 모두 기록됨화면에 할인 표시 없는 상품. 정상
다른 사이트에서 그대로 쓸 수 있는 컬럼title, price, review_count, image_url, source, captured_at, needs_review공통 컬럼으로 고정
사이트마다 바꿔야 하는 컬럼discount, is_ad, rankextractor 파일에서 사이트별로 처리

표에 확인필요 가 한 줄도 없다면 오히려 의심하세요. 실제 수집에서는 빈 값이 반드시 생깁니다. 빈 값을 드러내는 게 이 단계의 목적이에요.

💡 TIP
확장 프로그램이 끝내 동작하지 않았다면 수집결과_샘플.xlsx 를 대신 열어서 이 검토 실습만 먼저 진행하세요. 이 파일은 4교시_브라우저확장프로그램 폴더 바로 아래에 있어요. 검토 관점을 익히는 게 이 단계의 목적입니다.

결과에는 출처와 시점이 있어야 해요

가격과 리뷰 수는 계속 바뀝니다. 수집 결과는 언제, 어느 페이지에서 본 값인지를 함께 남겨야 나중에 검증할 수 있어요.

필드의미업무상 확인 포인트

구분사이트별 규칙결과

실습 1-D에서 비워 두었던 lib/site-extractors 폴더가 바로 이걸 위한 자리예요. 다른 사이트로 확장하기 위해 추출 규칙만 따로 분리해 두는 공간입니다. 사이트마다 화면 구조가 다르니까, 규칙 파일만 갈아 끼우면 팝업과 엑셀 저장 기능은 그대로 재사용할 수 있어요.

lib/site-extractors/
├─ coupang.js
├─ own-mall.js
├─ openmarket-a.js
└─ competitor-page.js

사이트마다 화면 구조는 다르지만, 업무자가 원하는 결과는 비슷합니다. 상품명, 가격, 리뷰 수, 이미지 URL, 상세 URL, 수집 시점, 확인필요 여부. 그래서 공통 컬럼은 유지하고 사이트별 선택자와 컬럼 매핑만 분리하면 됩니다.

여기까지 만들면 팝업에서 사이트를 고를 때 맞는 추출 규칙으로 전환되는 형태가 돼요. 쿠팡 이후에는 자사몰, 오픈마켓, 경쟁사 페이지처럼 공개 화면이 있는 업무 데이터로 넓혀갈 수 있습니다.
